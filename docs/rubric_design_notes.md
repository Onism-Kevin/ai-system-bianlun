# 评价量表设计说明（rubric.json v1.0）

> 任务：S1-9a + S1-9b。量表文件：`backend/app/rubric/rubric.json`。
> 本说明每个维度、每项权重都引用《思辨工坊项目完整方案.md》原文；
> 凡推断处显式标注"推断，依据 §X 的精神"。

## 1. 四维度及其出处

### D1 论证结构（argument_structure，0.30）

维度来自方案 §4.1D"论证结构分析"列举的结构要素：
系统将内容整理为"主张；理由；证据；反例；结论；支持、反驳、补充、依赖或限制等关系"。
评分对象即学生论证在这些要素上的齐备性与关系清晰度。

### D2 证据质量（evidence_quality，0.25）

维度来自方案 §3 第 2 条"反馈有依据：分析尽量指向用户原文、课程材料或可查看的来源"，
以及 §3 第 3 条"不确定性可见：无来源或证据不足时标记'待核实''AI 推断'或'需要人工判断'"。
§4.1D 亦要求"分析应提供原文片段或材料位置作为依据"——
证据质量衡量的正是学生论证是否满足同一条"可追溯"标准。

### D3 反驳与回应（rebuttal_response，0.25）

维度来自方案 §4.1C"人机论证训练"的核心循环：
"AI 根据学生当前论证提出针对性追问、反例或证据要求"，
训练模式含"教练式追问：逐步提示学生补足论证"与"反方对练：AI 针对学生观点提出挑战"。
评分对象是学生在这条主循环中的应对质量——**只评学生对追问的回应，不评追问本身**
（追问质量由 prompt 侧保障，属 S2-9 任务；报告 prompt 需写明此约束，属 S2-10）。

### D4 观点修订与反思（revision_reflection，0.20）

维度来自方案 §4.1E"观点修订与复盘"：
"保存初稿、修改稿和最终稿；展示版本差异；生成按统一量表组织的反馈；允许用户填写反思"。
§13.3 试点亦记录"学生是否根据反馈修订观点"。
反思文本作为本维度内部子项，不独立成第五维（用户 2026-10-13 裁定：保持四维简洁）。

## 2. 议题探索不进评估范围（用户 2026-10-13 裁定）

方案 §4.1A"议题探索"（关键概念和可能定义 / 讨论范围和边界 / 核心子问题 /
利益主体和分析视角 / 需要进一步查证的问题）**无任何评估维度覆盖，这是有意的**：

- 议题探索是**输入性任务**，其产出质量主要取决于 AI 拆解质量，而非学生能力；
  给它打分会把 AI 的表现计入学生能力，违背 §4.1E"AI 分数不得单独代表用户能力"。
- 学生在该环节的行为是"编辑、删除、补充系统生成内容"（§4.1A 原文）——
  这属于使用行为而非能力表现，MVP 无可靠量化锚点。
- 后果声明：若学生只做议题探索不做论证训练，报告对其**没有有效输出**；
  产品层引导（UI 提示继续训练）而非量表层补维解决。

## 3. 权重及其依据

权重方案为用户 2026-10-13 裁定采纳的 B（均衡）：0.30 / 0.25 / 0.25 / 0.20，合计 1.0。
方案原文未给出任何具体权重数值，逐项理由：

- **论证结构 0.30**：结构是基础但相对低阶——主张/理由/证据/反例/结论是骨架
  （§4.1D），但骨架齐备只是起点，不应压过核心能力维度。
- **证据质量 0.25**：差异化核心——"反馈有依据""不确定性可见"（§3-2、§3-3）
  是本产品与裸聊 AI 的分界线（§5.1），证据可追溯是差异化主张的主要承载维度。
- **反驳与回应 0.25**：训练产品核心能力——批判性思维的核心是"驳倒对方最强论点"；
  曾以"AI 追问质量影响分数"为由降权，被裁定不成立：解法是 prompt 保障追问质量
  （S2-9）+ 评分标准限定只评回应（本文件 §1-D3），不是降权。
- **观点修订与反思 0.20**：四维中权重最低，但 0.20 已体现"过程可复盘"的足够分量
  ——§3-4"过程可复盘"、§13.3"是否根据反馈修订观点"是试点核心观测项。
  受 §4.1E"AI 分数不得单独代表用户能力"约束，权重不高于核心能力维度。

## 5. 报告呈现约束（继承自方案，非本任务发明）

- §4.1E 原文："AI 分数不得单独代表用户能力。报告须展示量表、依据和建议。"
  → 报告出参必须同时含：量表版本（`rubric_version`）、逐维依据引用、改进建议三段。
- §13.2 要求评测覆盖"主张、理由、证据、反例抽取准确性"等七项——
  本量表四维度是**报告侧**的呈现结构，不替代 §13.2 的**评测侧**指标体系；
  两者关系：评测侧验证生成报告的工具是否可靠，量表侧规范报告说什么。
- schema_v3 报告表已有 `rubric_version VARCHAR(20)` 列，本版本号 `v1.0` 落库即此列值；
  量表改版只升版本号，不改旧报告（表注释："量表改版后旧报告仍可解释"）。

## 7. 档位描述设计依据（S1-9b）

三条写作原则（任务书硬约束）：①每条特征可观察、能在学生对话文本里定位证据
（否则 S2-10 无法给"依据引用"）；②相邻档差异具体可辨；③四维不套同一模板。

### D1 论证结构——依据 §4.1D 的七要素清单

描述围绕"齐备性 + 关系清晰度"递减：优秀=五要素齐+关系清晰+识别反例（§4.1D
"反例""仍未回应的问题"）；良好→合格逐档砍"反例意识→具体证据→贯穿性"；
未达标=无主张无理由层。优秀→良好的区分锚点是**是否识别反例**（用户范例指定）。

### D2 证据质量——依据 §3-2"反馈有依据"+ §3-3"不确定性可见"

评分轴是**可追溯性 + 核实状态**双降级：优秀=可定位原文片段+待核实显式标记
（§4.1D"分析应提供原文片段或材料位置作为依据"的镜像标准）；良好=来源具体
但片段不全；合格=笼统陈述"数据显示"式；未达标=断言冒充事实。优秀→良好
的区分锚点是**可定位性**，合格→待改进的区分锚点是**核实标记的有无**。

### D3 反驳与回应——依据 §4.1C"针对性追问、反例或证据要求"

评分轴是**对最强论点的处理质量**：优秀=先准确复述再回应（防稻草人，可从
对话文本直接判定）+指出关键假设+多轮累计推进；良好=回应主要论点+一处
假设/漏洞；合格=挑最弱处或局部曲解最强处；待改进=回避+自说自话；未达标=
各说各话。优秀→良好的区分锚点是**复述准确性与多轮推进**，不是"质量更高"。

### D4 观点修订与反思——依据 §4.1E"版本差异 + 反思"+ §13.3"是否根据反馈修订"

**哲学 A（用户 2026-10-13 裁定）：D4 评估"修订行为的质量"，不是"最终观点相对初稿的进步"**。理由：①哲学 B 会让初稿优秀者在 D1-D3 得高分后又被 D4 奖励一遍，维度混淆；②D4 的差异化定位是过程维度（§3-4"过程可复盘"、§13.3"学生是否根据反馈修订观点"），评估对象即修订行为本身。对上一轮审查两问的处置：初稿优秀、单稿即交且无反思 → 未达标（初稿质量由 D1-D3 计分，D4 只评修订与反思两项行为）；写 5 稿但每稿均为无关改写 → 待改进（有行为、无质量）。

评分轴是**方向性改进的广度 + 反思的具体度**：优秀=两类或更多方向性改进（补证据/修结构/回应反例，三类直接取自 §4.1B 观点建构要素与 §4.1D 结构要素）+反思具体说明"依据哪条反馈改了什么"；良好=两类+反思指出具体依据；合格=一类+反思有具体内容；待改进=有修订但改动无关（标点/措辞/重排）+反思缺失或套话；未达标=无修订记录且无反思。区分锚点：未达标 vs 待改进=**有无修订行为**；待改进 vs 合格=**修订有无方向性**；合格 vs 良好=**改进类别数**（1 vs 2）；良好 vs 优秀=**反思深度**（指出依据 vs 说明改了什么/为何——"两类或更多"与"两类"在恰好两类时重叠，由反思深度裁决）。
