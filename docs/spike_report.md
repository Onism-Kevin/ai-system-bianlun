## 七、乐观上界说明（spike ≠ 生产）

**spike 的 98.75% 首过合规率是一个乐观上界，不代表生产环境合规率。**
三条偏差来源：

1. **议题是精选的**：20 个议题经过类别均衡（5 类 × 4）与表述打磨，
   都是清晰、无歧义、无敏感触发的课程级议题。真实用户输入会有
   口语化、错别字、超长、自相矛盾、以及触及审核边界的敏感议题。

2. **prompt 是为 JSON 输出专门写的**：spike 的 5 套 prompt 只塞议题/立场
   与格式约束，长度短、结构干净。生产 prompt 还要塞用户历史对话、
   课程材料、权限上下文，长度与复杂度显著上升，挤压模型的格式遵循能力。

3. **spike 是单轮调用**：每 stage 独立调一次。生产是长对话 session，
   第 N 轮的上下文更长、干扰更多，第 N 轮首过合规率可能低于第 1 轮。

## 八、生产环境合规率预测区间（风险备注）

基于第七节三条偏差，给出**保守估计**：

| 场景 | 首过合规率估计 |
|---|---|
| spike（精选议题 + 专用 prompt + 单轮） | 98.75%（实测） |
| **生产预测（保守区间）** | **85% – 92%** |

**风险备注**：阶段二排期按 85% 首过合规率做缓冲假设。
- 若生产首过率跌到 85% 以下，`generate_structured` 的重试链路
  （S0-4）是兜底，但重试会把单次延迟推高（每次重试 ≈ 再一次完整调用），
  report 类长输出阶段尤其明显，可能加剧第六节的 UI 延迟问题。
- 不要假设"基本不会失败"——按 85–92% 区间准备重试预算与用户提示。

**重试对 report 延迟的量化**：按生产 85% 首过率假设，report 阶段约 15%
调用会重试一次，P85 延迟可能从 57.6s 推至约 85s。S2-F7 的 UI 超时/进度
提示应按 P85 设计，不按中位数。
